# i18n DE/EN (ganze Website) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Die ganze Website (One-Pager, 404, Impressum, Datenschutz, AGB) gibt es zusätzlich auf Englisch unter `/en/…`, umschaltbar über einen „DE / EN“-Schalter im Vollbild-Menü unter „Kontakt“; die deutsche Seite bleibt unter den heutigen URLs unverändert.

**Architecture:** Alle Routen wandern unter `app/[lang]/` mit dem Root-Layout dort (`<html lang>` serverseitig). `src/proxy.ts` schreibt unpräfixierte Pfade intern auf `/de/…` um und leitet `/de/…` per 301 zurück. Copy liegt in zwei typgleichen TS-Dictionaries, sprachneutrale Assets bleiben in `constants.ts`; Server-Komponenten mergen beides und reichen fertige Props an die (Client-)Sections. Rechtstexte liegen als JSX-Content-Module je Sprache unter `src/content/legal/`.

**Tech Stack:** Next.js 16.4.6 (App Router, Proxy, `next/root-params`), React 19, TypeScript, Tailwind v4, GSAP/Lenis (unberührt), Node 22 `node --test` mit nativem Type-Stripping, Playwright (vorhanden, für die Gerätematrix).

**Spec:** `docs/superpowers/specs/2026-11-24-i18n-de-en-design.md`

## Global Constraints

- Locales nur `"de"` | `"en"`. DE ohne Präfix (`/`, `/impressum` …), EN unter `/en` (`/en`, `/en/impressum` …). Slugs in beiden Sprachen gleich.
- Keine Browser-Spracherkennung, kein `Accept-Language`, kein Cookie, kein `localStorage`.
- Keine neuen npm-Abhängigkeiten.
- Desktop-Choreografie eingefroren: keine Änderung an `src/hooks/*`, `src/lib/breakpoints.ts`, GSAP-Timelines, ScrollTrigger-Konfiguration. Einzige sichtbare Desktop-Änderung: der Schalter im geöffneten Menü (Kopfleiste unverändert).
- DE-Copy bleibt zeichengleich, auch Eigenheiten wie „Lust auf ein Projekt ?“, „schreib mir - dann starten wir.“, „Strasse und Hausnummer“.
- `usePathname()` kommt im Projekt danach nicht mehr vor (Hydration-Mismatch mit Proxy-Rewrite, siehe `node_modules/next/dist/docs/01-app/03-api-reference/04-functions/use-pathname.md`).
- Client-Komponenten importieren nie `@/lib/i18n/dictionaries` (sonst landen beide Sprachen im Client-Bundle).
- Zwischen Seiten und beim Sprachwechsel `<a>`, nie `next/link`.
- Kapitel-IDs der Rechtsseiten (`LegalSectionData.id`) sind in DE und EN identisch, damit der Hash beim Sprachwechsel trägt.
- Kein `dynamicParams = false` irgendwo unter `app/[lang]` (schließt in 16.4 das ganze Routen-Tupel, die 404 fiele auf Nexts ungestylte Default-Seite).
- EN: US-Englisch, „du“ → „you“, direkt und persönlich, sinngemäß statt wörtlich. Hinweis auf EN-Rechtsseiten exakt: „This is a courtesy translation. Only the German version is legally binding.“
- `og:locale`: `de_DE` / `en_US`.
- Vor dem Schreiben von Next-Code die Guides in `portfolio/node_modules/next/dist/docs/01-app/` lesen: `02-guides/internationalization.md`, `03-api-reference/03-file-conventions/proxy.md`, `…/not-found.md`, `…/layout.md`, `03-api-reference/04-functions/next-root-params.md`, `…/generate-static-params.md`, `…/generate-metadata.md`, `…/03-file-conventions/01-metadata/sitemap.md`.
- Arbeitsverzeichnis für Befehle: `portfolio/`. Prüfserver: `pnpm build && pnpm start` (Port 3000). Nie `pnpm build` neben laufendem `pnpm dev`.
- Git: Branch `feat/i18n-de-en`, ein Commit pro Task, Commit-Nachricht deutsch im Repo-Stil („Bereich: was passiert“), mit Zeile `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Kein Push.
